# Cosmos EVM v0.6.5 -> v0.6.6 Migration

v0.6.6 is a state-breaking patch release. It changes how a `MsgEthereumTx` is authorized for execution, which
requires action from chains with a custom EVM ante handler.

## Key change

The `MsgEthereumTx` msg handler now rejects a message unless the EVM ante handler verified it, for the same sender, in
the same tx. The signature, nonce and fee of an Ethereum tx are only checked by that ante handler, so a
`MsgEthereumTx` dispatched by another msg (authz `MsgExec`, a governance or group proposal, an interchain account, a
custom module) used to execute without those checks.

`MonoDecorator` records the verified sender with `EVMKeeper.SetAnteVerifiedSender`, and the msg handler consumes that
record. The record lives in the `x/vm` transient store, so it never outlives the block.

## Required actions

- Chains that use `ante.NewAnteHandler` or `MonoDecorator` need no change.
- Chains with a custom EVM ante handler must call `SetAnteVerifiedSender(ctx, ethTx.Hash(), sender)` after the
  signature, nonce and fee checks pass. Without it every Ethereum tx fails with
  `MsgEthereumTx is only executable as the single message of an Ethereum tx`.
- Implementations of `ante/interfaces.EVMKeeper` must add the `SetAnteVerifiedSender` method.
- Code that calls `Keeper.EthereumTx` directly, such as tests, must record the sender first. Tests can use
  `testutil/integration/evm/utils.ExecuteAnteVerifiedEthereumTx`.

## Optional: deny other msgs to dispatching modules

No router change is needed for `MsgEthereumTx`. The msg handler check covers every module that dispatches msgs, so
keep passing `app.MsgServiceRouter()` to the authz, gov, group and ICA host keepers.

The check only covers `MsgEthereumTx`. If your ante handler enforces a security rule on another msg type that its msg
server does not enforce again, a module that dispatches msgs (authz, gov, group, the ICA host, a contract module) calls
that msg server without the rule being checked. `ante/cosmos.NewDenyListMsgRouter` is added for this case: pass it, in
place of `app.MsgServiceRouter()`, to the keeper of every such module, with the type URLs to block.

```go
deniedMsgRouter := cosmosante.NewDenyListMsgRouter(
    app.MsgServiceRouter(),
    sdk.MsgTypeURL(&customtypes.MsgCheckedByAnteHandler{}),
)
```

The router only covers the keepers it is passed to. Where you can, enforce the rule in the msg server instead.

## Operator guidance

- The change is state-breaking, so all validators must upgrade at the same height through a coordinated upgrade.
